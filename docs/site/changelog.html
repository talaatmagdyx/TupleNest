Current release

v0.1.0-beta.11

Public BetaAugust 2026

Exporting a large result no longer freezes the app, and the editor stops fighting long queries.

Fixed

  • Exporting a large result froze the app. Every row was fetched, the whole document was built as one string, and only then was the save panel shown — all on the main thread, in one unbroken stretch. Nothing yielded, so the window could not paint or take a click for as long as it took, and the document existed about three times over at the peak. Exports now stream: the save panel opens first, then rows are written a page at a time.
  • A running export could not be stopped. It has a progress bar and a Cancel button now. Cancelling is checked between pages, never mid-write, and it deletes the partial file — a truncated CSV opens, parses, and is missing rows with nothing on its face to say so.
  • Copying a large result froze it too. The clipboard takes one string or nothing, so that path cannot stream; it is capped at 10,000 rows instead, and the count says when it capped.
  • A row count could hide what an export left out. It reported missing rows only when the result store had overflowed, so rows dropped by a format cap were not mentioned. It now compares what was written against the true total.
  • HOT on a node that cost 0.3 ms. The hot-spot badge was a cost ranking with no wall-clock floor, so a query finishing in a fraction of a millisecond still got a full-width red bar. It now honours the same 1 ms floor the bottleneck flag always had.

Added

  • The editor wraps long lines. A 300-character ANY(ARRAY[…]) no longer runs off the right edge, and line numbers stay with their line when it wraps to several rows.
  • Tab indents, Shift-Tab outdents. Tab used to do nothing but move focus out of the editor, so a block could not be indented at all. Escape still arms the next Tab to move focus, so the editor is not a keyboard trap.
  • Enter keeps the indentation, adds a level after an opening bracket, and pushes a waiting closer onto its own line.
  • Brackets and quotes auto-close, wrap a selection, and step over a closer rather than doubling it — without splitting a word, so don't does not become don''t.
  • Planning time leads when it dominates. On a partitioned table the planner can spend far longer choosing a plan than the executor spends running it — a ratio that was sitting quietly in the stats list while every insight above it described the smaller half of the query.

Both of these came from using the app rather than testing it: a wide ANY(ARRAY[…]) query that ran off the edge of the editor, and an export that hung the window long enough to look crashed.

v0.1.0-beta.10

BetaJuly 2026

The plan reader stops asserting things that are not true.

Fixed

  • An index was recommended for queries with nothing to index. Any Seq Scan earned “an index matching its filter could avoid the full scan”, whether or not it had a filter. On a bare select * … limit 1 there is no WHERE, so that sends you after a predicate that does not exist. All three code paths now check for a Filter, Index Cond or Recheck Cond, and where there is none they say the true thing: the scan reads the whole table and narrowing the query is the only lever.
  • Pruned partitions were scored for row-estimate accuracy. A branch the executor never reached reports 0 rows because it was skipped, not because it found nothing — so every pruned partition earned an alarming EST 100k× OFF badge. There is no actual count to compare against, so no verdict is offered.
  • The stale-statistics advice was wrong under a LIMIT. The planner estimates the whole set and is never asked for it, so the shortfall is arithmetic rather than staleness — yet the panel told you to run ANALYZE on a perfectly healthy table. It now names the LIMIT and says the discrepancy is expected.
  • Ratios read at a glance — 1.5M× rather than ×1499292. The extra digits were false precision you had to count before they meant anything.

All four were found by looking at one real plan, not by any test. The tests passed throughout because they asserted the shape of the output rather than whether it was correct — and one of them had been passing for the wrong reason, on a fixture with no filter. An analysis tool can be fully covered and still be confidently wrong.

v0.1.0-beta.9

BetaJuly 2026

Three things that used to have a ceiling: the size of a file you could import, the resolution of a plan comparison, and how far a schema diff got you.

Added

  • CSV import streams the file instead of loading it. Import read the whole file into one string and held every parsed row in state, so it was bounded by RAM rather than by patience. The parser is now an incremental state machine — the obvious fix, split on newlines and parse each line, is wrong, because a quoted field may legally contain the delimiter, a newline, or both, so a read boundary can land inside a value. Measured on a 358 MB file of 6,000,001 rows: peak memory growth 15 MB streaming, against heap exhaustion and a dead process on the old path. Because the row total is genuinely unknown until the file has been read, the UI stops claiming one: progress is percent-of-bytes and the preview says "first 500 rows sampled".
  • Plan comparison goes node by node. It could tell you the query got 30% costlier and that a Seq Scan appeared, but not which node absorbed the time. Trees are now aligned and each node reports its own delta. Where two siblings look identical — an Append over matching partition scans — position is the only signal, and position is not evidence, so those pairs are labelled ambiguous rather than shown with the same confidence as the rest.
  • A schema diff can now write the migration. Reviewable ALTER DDL with three risk levels that mean something: safe, review, and destructive — DROP TABLE, DROP COLUMN — which come back already commented out, so pasting the script whole cannot run them. TupleNest generates it and never executes it; there is no run button and there will not be one.

Fixed

  • The generated migration named the wrong schema. A diff of left → right describes what left is missing, so the DDL belongs to left; it was addressed to right — the schema that already had the new column. Pasted and run, it would have errored on the first ADD COLUMN. Every test covering the generator asserted the statement kind and none asserted the schema name, so all of them passed throughout. Found by applying the output to a real database.
  • An added NOT NULL column came back nullable, because the column diff carried the type and not the nullability. The constraint is now a second, review-level statement: ADD COLUMN ... NOT NULL fails outright on a populated table, so the honest form is add nullable, backfill, then SET NOT NULL.
  • An import left the explorer stuck on "Loading schemas…", because finishing one dropped the cached catalog without re-reading it — emptying every schema picker in the app until you reconnected. And "Compare schemas…" opened on find-usages: three palette commands share one modal and all three landed on its first pane.

The migration generator was verified by round trip against a live PostgreSQL 18, taking the statements from the UI rather than writing them by hand: two schemas differing by an added column, a dropped column, a retyped column, an added table and a dropped table; the generated script applied to a copy of the left schema; the result re-diffed against the right. Schemas are identical. That round trip is why this entry is trustworthy and an earlier draft of it was not — it had claimed the same result on the strength of statements assembled by hand, and it was wrong twice over.

v0.1.0-beta.8

BetaJuly 2026

The plan analyzer stops describing the problem and writes the statement that fixes it.

Added

  • The plan analyzer now writes the index, not just the advice. When a plan scans a table sequentially to apply a filter — or an already-indexed scan throws away a lot of rows to a residual filter — the analyzer reads that filter's columns and produces a runnable CREATE INDEX with a copy button. Equality columns first, then a single range column: the one ordering a btree can actually seek on.
  • Expression indexes, decided from the column's real type. A filter on lower(email) or date_trunc('day', booked_at) gets the matching CREATE INDEX ON t ((expression)), with the expression preserved character for character — the planner only uses one that matches the query verbatim. CREATE INDEX rejects anything not IMMUTABLE, and volatility depends on the argument type, so the advisor reads the type from the catalog: date_trunc on a timestamp is offered, the same call on a timestamptz is not.
  • It stays silent when a plain composite btree is the wrong answer — an OR between predicates, a join condition, an inequality, or an expression it has no volatility evidence for. A suggestion that errors out costs more than no suggestion.

Every suggestion was verified end to end against a live PostgreSQL 18 on a 600k-row table: build what the advisor proposes, re-run EXPLAIN, confirm the planner abandons the sequential scan. 17 of 17 cases behaved as designed — 1.9× to 1461× faster where an index is offered, silence where one cannot be built. These are candidates to verify, not promises: the advisor reads the filter, not the table's data distribution.

v0.1.0-beta.7

BetaJuly 2026

The editor works before you connect, and two controls a screen reader could not name now have names.

Fixed

  • The SQL editor is usable before you connect. It was disabled until a connection was up, which made drafting a query, searching it with ⌘F, commenting it with ⌘/ and formatting it all impossible in exactly the state where you would do them — two of those shipped in the release before this one. Only running a query needs a server now; the Run button and the "Not connected" note already say so.
  • Two controls a screen reader read as unlabelled now have names. The command palette's search box announced only as "text box", and each query-parameter field ($1, $2, …) had a visible label that was not tied to it. Both fixed; an audit confirmed these were the only two controls in the app lacking an accessible name, and a stale note claiming the connection form was unlabelled — it is fully labelled — was corrected.

v0.1.0-beta.6

BetaJuly 2026

The editor grows the two things it was missing, and a safety feature that existed but could not be switched on.

Added

  • A query timeout you can actually set. PostgreSQL's statement_timeout has worked in the driver since Phase 0, with a live test proving the server cancels a five-second sleep after 250 ms — but the value was hard-coded to 0 on the way through the app, so the feature existed and was unreachable. Now a per-connection setting in seconds, beside the read-only toggle. Empty or 0 still means no limit, which is PostgreSQL's own meaning and the right default for an IDE. It is the server's own timer, so it fires even if the app is busy or you have walked away.
  • Find and replace (⌘F). Match count as you type, Enter and Shift+Enter to step, a case toggle, replace and replace all. Literal text rather than a regular expression: half the characters people search for in SQL — ( ) . * $ [ — are regex syntax, so a pattern box would need escaping for the common case and serve the rare one.
  • Comment and uncomment lines (⌘/). Line comments, not block comments, because PostgreSQL nests block comments. The marker goes in at the shallowest indentation so a block keeps its shape, and a half-commented block comments fully rather than half-uncommenting — so pressing twice returns exactly what you started with.

Changed

  • The keyboard shortcuts are described in one place. The key handler, the in-app cheatsheet and this website each kept their own list, and all three disagreed: the app bound ⌘⇧L, ⌘O, ⌘B and ⌘P while the cheatsheet mentioned none of them, and the site listed two that were never bound to anything. Press ? and you now see all of them. A test reads the handler's source and fails if it finds a key comparison of its own, because the failure that matters is a binding added somewhere the cheatsheet never hears about.

v0.1.0-beta.5

BetaJuly 2026

The plan reader tells the truth about what it was given.

Fixed

  • A pasted plan and the same plan in FORMAT JSON now produce identical results. Cross-validating against a second PostgreSQL major turned up five disagreements, two of them structural. A SubPlan's body attached to whichever node preceded it rather than the one enclosing it — moving its time to the wrong node and badging the wrong one as the bottleneck. A CTE Scan at the top of a plan was swallowed as if it were a CTE label.
  • A HashAggregate that spilled to disk was never flagged on the JSON path — the path used for every query run inside the app — because the server files an aggregate's batch count under a different key than a hash node's, and only the second was checked.
  • The text format packs parallel-awareness, partial mode, aggregate strategy, join type and the write operation into the printed node name, where JSON keeps each in its own field. The same plan drew different node names depending on which format it arrived in; the text reader now speaks JSON's vocabulary. VERBOSE's schema qualification and a filter that discarded nothing are handled for the same reason.

Added

  • A pasted plan that is only part of a plan now says so. A fragment parses perfectly well, and that is the danger: the analysis looks exactly as confident as one from a whole plan while its percentages are measured against the wrong total. Two cases are detected — a paste whose top was cut off, and one that stops mid-line — and each is explained in terms of what it does to the numbers on screen. Orphaned nodes are no longer adopted into the first one either: inventing a parent hands it their time.
  • The File menu reaches the plan analyser — the one feature that works with no connection, and so the one nobody thinks to look for in a sidebar built around a database. (macOS and Windows; the platform default has no File menu on Linux, where the activity rail and command palette still reach it.)

v0.1.0-beta.4

BetaJuly 2026

Query plans: understanding them, and analysing one you were sent.

Added

  • Analyse a plan you paste — no connection, nothing leaves the machine. TupleNest now reads PostgreSQL's text EXPLAIN output — the indented tree people actually copy out of psql, a ticket, or a colleague's message — as well as FORMAT JSON. It detects which as you type and runs the same analysis it runs on its own queries. The reason to build it is privacy, not convenience: the usual way to get a plan analysed is to paste it into a website, which hands a third party your table names, index names, filter conditions and sometimes literal values out of production. Open it from the activity rail or the command palette — deliberately available while disconnected, since the point is a server this app cannot reach.
  • The text parser was validated against the server itself: ten queries captured as both FORMAT TEXT and FORMAT JSON from a live PostgreSQL 18 — parallel scan, external-merge disk sort, hash spill, a nested loop repeating 20,000 times, a never-executed branch, a CTE, a SubPlan/InitPlan, a trigger, a discarding filter, and a plain scan — then both parsed and compared. All ten agree on node count, depth, loops, rows, estimates, rows removed, blocks, temp blocks, flags, statistics and insights.
  • Richer EXPLAIN ANALYZE plan view. The plan highlights the real bottleneck by self-time — a node's wall time minus its children's — rather than only the costliest sequential scan. A nested loop's inner side really does run once per outer row, so its loops are multiplied; but a node under a Gather reports one “loop” per parallel worker and those run at the same time, so workers are divided back out and the numbers add up to the execution time.
  • Nodes are badged for rows read and then discarded by a filter, sorts that spilled to disk, hashes that spilled to multiple batches, blocks served from disk rather than cache (attributed to the node that actually read them, since PostgreSQL reports buffers cumulatively), estimates that missed by 10× or more, very high loop counts, and branches the executor never reached.
  • Time no node accounts for is surfaced: JIT compilation and trigger time both sit outside the plan tree, and a statement can spend most of its wall clock there. An ordered list of insights turns all of it into next steps.

Fixed

  • Hostnames, role names and key paths are no longer rewritten by macOS. With “capitalize words automatically” on, a typed postgres became Postgres the moment the field lost focus. PostgreSQL role names are case-sensitive, so the connection failed at authentication and looked exactly like a wrong password — with nothing on screen to say the text had been edited after it was typed.
  • The statistics panel says why it is empty. Choosing a non-JSON EXPLAIN format left a bare “—” where an explanation belonged.

Changed

  • The status bar identifies the build it is running — commit and build time, with a trailing + when built from a tree with uncommitted changes. An installed release and a local build are otherwise identical on screen, and telling them apart had already cost an afternoon of debugging a fix inside a window that could not have contained it.
  • CONTRIBUTING.md gains a “Building a real .app locally” section: tauri dev serves the UI from a dev server and goes blank when that server stops, and tauri build refuses without a signing key because releases always ship updater artifacts.

v0.1.0-beta.3

BetaJuly 2026

The security-review response: the release blockers (TLS, numeric DoS, CSV injection), plus data/local/desktop hardening.

Security

  • TLS is now actually required in the verify modes (CRITICAL). The client never set the SSL mode, defaulting to prefer; verify-ca/verify-full now map to require and refuse plaintext — proven against a real ssl=off server with a negative control.
  • A malicious server can no longer OOM the app via a numeric value (HIGH). The wire display scale was read signed and cast to a huge loop bound; now read unsigned and clamped, with digit/render ceilings.
  • CSV export neutralizes spreadsheet formula injection (HIGH). Cells starting with = + - @ (or tab/CR) are neutralized by default; a toggle allows raw output.
  • On-disk stores, logs, and crash reports are now owner-only on Unix (0700 dir / 0600 files).
  • Stored SQL is scrubbed of secret literals; -- tuplenest:no-history skips a statement's history row.
  • A single huge cell can no longer spike memory — rendered values capped at 1 MiB with a truncation marker.
  • Keychain entries are no longer orphaned on every Test/connect — a held reference is reused.
  • Exports go through a Rust command that owns the save dialog; the fs plugin was removed. CSP tightened (object-src/base-uri/frame-ancestors none).
  • Auto-update anti-rollback floor; release logging caps chatty crates to warn.
  • All third-party GitHub Actions pinned to commit SHAs; CI runs least-privilege.
  • Failed-query history no longer persists row values — only title, SQLSTATE, and category.
  • Deterministic fuzz (300k+ inputs) over the numeric and raw-value decoders.

Fixed

  • A failed query now shows the server's full report (SQLSTATE, message, DETAIL, HINT, CONTEXT), not the bare “Database error”.

v0.1.0-beta.2

BetaJuly 2026

One real bug, found by the first macOS tester within an hour of beta.1 — which is exactly what betas are for.

Fixed

  • The window close button did nothing. The close guard ended in destroy(), but the capability file granted only core:default, which doesn't include allow-destroy. One granted permission was the whole fix.
  • The same gap silently broke the open-transaction close prompt — “Commit & quit” / “Rollback & quit” could never actually quit. Both are now verified against a live database.

Added

  • A test that scans the frontend for every getCurrentWindow() call and asserts the capability grants it — verified by removing the permission and watching it fail.

Docs

  • README rewritten: sixty-second quick start, real keyboard map, honest “what TupleNest is not (yet)”.
  • Corrected what a Windows code-signing certificate actually buys (OV doesn't skip SmartScreen; only EV does).

v0.1.0-beta.1

BetaJuly 2026

First public release — to put it in front of real users, because “is the UX intuitive” is a question no test suite can answer.

Fixed (pre-launch review)

  • The open transaction now has an owning tab; committing from another tab is refused and names the owner.
  • Row edits check rowsAffected; a statement must touch exactly one row or the set rolls back.
  • The destructive-statement guard masks comments/strings first — a commented-out WHERE no longer disarms it.
  • Read-only profiles issue a real read-only session characteristic instead of being hard-coded off.
  • Terminating a backend asks first; generated/identity columns are read-only; the grid footer counts the real total.

Added

  • SECURITY.md, PRIVACY.md, the changelog.
  • CI runs contract tests against real PostgreSQL 13, 15, and 17 with TLS enabled.
  • Read-only connection profiles.

Known limitations

  • macOS builds not notarized; Windows installers unsigned — first launch needs one extra click.
  • CSV import reads the whole file into memory.
  • Nobody has lived with this yet. That's what the beta is for.
