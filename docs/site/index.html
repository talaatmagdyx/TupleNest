Why TupleNest

Built around the mistake
you only make once.

Two engines, one safety model, and a clear answer to "where does my data go?".

Production-aware

The worst statements stop and ask on any connection. Tag it prod or staging and more of them ask, and the worst ones make you type the table name.

Enforced, not hoped

Read-only profiles are set on the PostgreSQL session and re-checked before every statement; SQLite opens the file read-only.

Local-first

No account and no telemetry. Passwords in the OS keychain. Prod query text never written to history.

AI on your terms

Your own Anthropic key or a local Ollama model. It is never sent result rows and never runs anything by itself.

THE SAFETY MODEL

Production safety is a workflow, not a warning colour.

Each protection names what actually enforces it.

  • Read-only set on the PostgreSQL session and re-checked before every statement; SQLite files opened read-only
  • Statement guard on prod and staging: no-WHERE writes, DROP, TRUNCATE, ALTER and more ask first
  • Type the name for an unbounded write, a DROP or a TRUNCATE on prod and staging
  • Audit before run on prod and staging: if the audit row can't be written, the statement isn't sent
  • No prod SQL in history, and a 20,000-row stop at the limit
  • TLS verify-full by default; SSH host keys verified, passphrase keys supported
The guard is a seatbelt light, not the seatbelt. A database role without write privileges is the hard boundary — use one for production data that must not change.

THE ASSISTANT

Explain, fix and write SQL — without sending your rows.

Use Claude with your own Anthropic API key, or a local model through Ollama. Requests are made by the Rust core; the window never holds your key.

  • Sent: your message, the editor's SQL, error text with row-quoting lines removed, schema names and types
  • Never sent: result rows, history, the connection's host, user or password
  • Ollama cloud models are labelled and refused until you opt in
  • Nothing runs by itself: suggestions go through Run, the guard and the audit log
MCP server

Let your AI tools in — one connection at a time.

Claude Desktop, Claude Code or Cursor can query your saved connections through TupleNest's rules. The app's own binary serves MCP on stdio: tuplenest-desktop mcp.

Off

The default for every connection. It is not listed, and naming it gets the same answer as a name that does not exist.

Read only

A server-enforced read-only session plus the read allowlist. The most prod and staging can ever get.

Read and write

Writes run, but anything the guard would ask about is refused with the reason — no one is there to confirm.

Claude Desktop / Cursor

// claude_desktop_config.json or ~/.cursor/mcp.json
{
  "mcpServers": {
    "tuplenest": {
      "command": "/Applications/TupleNest.app/Contents/MacOS/tuplenest-desktop",
      "args": ["mcp"]
    }
  }
}

Claude Code

claude mcp add tuplenest -- \
  "/Applications/TupleNest.app/Contents/MacOS/tuplenest-desktop" mcp
The path is a macOS placeholder — Settings › MCP server shows the one for your install. Statements on prod and staging are audited before they run, recorded as MCP · <client>. What a query returns goes to that AI tool.
