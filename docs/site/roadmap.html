Product principles

How we decide what to build

Two engines, done properly

PostgreSQL and SQLite, and no others. Depth beats shallow support for ten.

Safety before convenience

A feature that makes accidents easier doesn't ship.

Local-first

Your data and credentials stay on your machine.

Native performance

A Rust core, bounded memory, fast startup.

Honest claims

If it isn't built and tested, it's marked planned.

Open development

Built in public, decided in the open.

Not planned

What TupleNest won't become

Saying no keeps the product focused. These are deliberate non-goals.

  • Other database engines. No MySQL, MariaDB, SQL Server, MongoDB or Redis: PostgreSQL and SQLite only
  • A hosted or cloud service. No cloud-hosted query execution, no cloud sync, no server of ours in between
  • Sending your data to an AI. The assistant sends your question, the query and schema names only, never rows
  • Advertising-based monetization
  • Mandatory accounts
  • Telemetry that is on by default, or that includes query text or row data
An AI tool you connect over MCP gets what the connections you turn on for it return — that is what MCP is for. Every connection starts off. See the Security page.
